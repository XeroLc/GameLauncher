# GameLauncher 云同步配置指南

GameLauncher 的「增量云同步」可以把游戏数据库（`games.db`）和游戏图片（`GameLauncher_Images`）增量备份/同步到远端，支持两种后端：

- **本地同步文件夹**：适合 OneDrive、Dropbox、Syncthing 等已有同步工具的目录
- **Cloudflare R2**：通过 S3 兼容 API 直接上传到 R2 对象存储

入口：设置 → **增量云同步**。

---

## 1. 功能说明

### 同步范围

| 会同步 | 不会同步 |
|---|---|
| `games.db`（游戏数据库） | `settings.json`（含本机 R2 密钥，避免云端泄露） |
| `GameLauncher_Images/`（图标、预览图） | `crash_log*.txt` |
| 其他本地数据目录下的文件 | SQLite 的 `-wal` / `-shm` 临时文件 |
|  | 同步清单本身（`.sync/` 目录） |

> 数据目录位置：`%LOCALAPPDATA%\GameLauncher`

### 同步方向

| 方向 | 行为 |
|---|---|
| 双向同步（默认） | 本地和远端互相传播变更，删除也会同步 |
| 仅上传备份 | 只把本地变更传到远端，远端多余文件不动 |
| 仅下载恢复 | 只把远端变更拉到本地，本地多余文件不动 |

### 增量机制

- 每次同步先扫描两侧文件的 **大小 + 修改时间**，只在变化时才计算哈希并传输
- 本地清单保存在 `%LOCALAPPDATA%\GameLauncher\.sync\manifest.{folder|r2}.json`
- 首次同步为全量，之后的同步只传输变化部分
- 两侧同时变更时，以修改时间较新的一侧为准

### 删除保护

同步导致的删除不会直接丢失文件：

| 位置 | 回收站 |
|---|---|
| 本地 | `.sync/trash/` |
| 同步文件夹 | 远端目录下的 `.trash/` |
| Cloudflare R2 | 桶内的 `_trash/` 前缀 |

需要时可手动恢复。

## 2. 方式一：本地同步文件夹

适合已经使用 OneDrive、Dropbox、Syncthing、坚果云等工具的用户——GameLauncher 先把数据同步到本地文件夹，再由该工具上传到云端。

### 配置步骤

1. 准备一个专用的同步文件夹（例如 `D:\CloudSync\GameLauncher` 或 OneDrive 下的目录）
2. 打开 GameLauncher 设置 → 增量云同步
3. 开启「启用云同步」
4. 同步方式选择 **本地同步文件夹**
5. 点击「浏览」选择同步文件夹（或手动输入路径）
6. 选择同步方向和自动同步间隔
7. 点击「测试连接」（确认文件夹可写），再点「立即同步」

### 注意事项

- 同步文件夹**不能**是本地数据目录本身或其子目录
- 建议使用空目录或专用目录，避免和无关文件混在一起
- 若希望多台电脑共用同一份数据，需要确保所有电脑都指向同一个云端同步目录（例如同一 OneDrive 账号）

## 3. 方式二：Cloudflare R2

### 3.1 前置准备（Cloudflare 后台）

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com)
2. 左侧进入 **R2**
3. **创建 Bucket**：点「Create bucket」，起名如 `gamelauncher`（建议专用空桶）
4. 在 R2 概览页记下 **Account ID**（32 位十六进制字符串）
5. 创建 R2 API Token：
   - 进入 **Manage R2 API Tokens** → **Create API Token**
   - 权限选择 **Object Read & Write**（对象读写）
   - 存储桶限定到你刚创建的桶
   - 创建成功后，页面会显示以下信息：

| 页面字段 | 用途 |
|---|---|
| 令牌值（Token value，`cfat_...`） | 给 **Cloudflare API** 用的，**不要**填进 GameLauncher |
| 访问密钥 ID（Access Key ID） | 填进 GameLauncher 的 Access Key ID |
| 机密访问密钥（Secret Access Key） | 填进 GameLauncher 的 Secret Access Key |

> ⚠️ 最容易踩的坑：把「令牌值」(`cfat_...`) 当成 Secret Access Key 填进去，会报 `403 SignatureDoesNotMatch`。
> 机密访问密钥只在创建时显示一次，丢失后无法查看，需要 Revoke 重建。

### 3.2 GameLauncher 配置

打开设置 → 增量云同步：

1. 开启「启用云同步」
2. 同步方式选择 **Cloudflare R2**
3. 填写以下字段：

| 字段 | 填写内容 | 示例 |
|---|---|---|
| R2 Endpoint | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` | `https://b3ae03a2bc66f29e3abe4b2f220fac32.r2.cloudflarestorage.com` |
| Bucket 名称 | 创建的桶名（区分大小写） | `gamelauncher` |
| Access Key ID | R2 API Token 的访问密钥 ID | `bae7742f4de1dd2217f54cbda5c0a323` |
| Secret Access Key | R2 API Token 的机密访问密钥 | `58b6eb35...`（64 位十六进制） |

4. 选择同步方向（一般用默认的「双向同步」）
5. 选择自动同步间隔，或保持「手动」
6. 点 **测试连接**，看到「连接成功，配置可用」后
7. 点 **立即同步** 开始首次同步

### 3.3 密钥安全

- Secret Access Key 使用 Windows DPAPI 加密后保存在本机 `settings.json`
- `settings.json` **不会**被同步到 R2
- 换电脑后需要在新机器重新填写 R2 凭据
- 不要在聊天、截图或任何公开渠道泄露 Secret；一旦泄露，请到 R2 → Manage R2 API Tokens 立即 Revoke 重建

## 4. 自动同步

在「自动同步间隔」中选择：

| 选项 | 行为 |
|---|---|
| 手动 | 只在点击「立即同步」时执行 |
| 每 5 / 15 / 30 / 60 分钟 | 定时自动同步，启用后 30 秒会先执行一次 |

同步历史保留最近 50 条，可在设置界面查看。

## 5. 常见问题排查

### 5.1 测试连接失败

| 报错 | 原因 | 解决 |
|---|---|---|
| `Unauthorized (401)` | Access Key ID 无效 | 检查是否把 Account ID 或旧 Key 填进了 Access Key ID |
| `SignatureDoesNotMatch (403)` | Secret 与 Access Key ID 不配对 | 确认使用的是「机密访问密钥」而不是「令牌值」`cfat_...`；必要时 Revoke 重建 Token |
| `NoSuchBucket (404)` | Bucket 名称或 Endpoint 错误 | 检查桶名大小写、Endpoint 中的 Account ID |
| 连接超时 | 网络无法访问 R2 | 检查网络/代理/防火墙，或稍后重试 |
| 测试连接成功但上传失败，报 `STREAMING-AWS4-HMAC-SHA256-PAYLOAD not implemented` | 旧版本程序的 AWS SDK 流式签名与 R2 不兼容 | 更新到包含 R2 兼容性修复的版本后重新同步 |

### 5.2 「立即同步」按钮不可用

- 确认「启用云同步」已打开
- 确认后端配置完整：
  - 文件夹后端：同步文件夹路径存在
  - R2 后端：Endpoint、Bucket、Access Key ID、Secret Access Key 四项都填了

### 5.3 同步成功但数据没变化

- 首次同步后，如果两侧没有变更，第二次同步会显示「跳过」而不是重新上传，这是正常的增量行为
- 检查同步方向：若选择「仅下载」，本地变更不会被上传

### 5.4 换电脑恢复数据

1. 新电脑安装 GameLauncher
2. 配置同样的同步方式（R2 需要重新填凭据；文件夹方式需要先让 OneDrive 等工具同步完成）
3. 选择「仅下载恢复」或「双向同步」
4. 点「立即同步」，数据会下载到本地

---

## 6. 建议

- R2 桶建议专用，不要与其他数据混用
- 重要数据仍建议定期使用「导出数据」生成 `.gldata` 备份
- 首次同步前确认网络稳定；桶内对象较多时首次全量会耗时较长
- 云同步是辅助手段，不能替代本地备份
